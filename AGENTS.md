# AGENTS.md - hermes-engagements

Hermes plugin that gives agents a maintained, file-based client foundation. This file is for coding agents and contributors working in this repository.

Read first: `docs/SPEC.md` is the build contract, `docs/TOOLS.md` is the normative tool contract, and `docs/RUNTIME-EVIDENCE.md` records what has actually been run and on which surface. If a change alters documented behaviour, amend the document in the same change.

## Rules

- Fixtures, tests, docs and demos use fictional clients only (Acme Bakery, Riverbend Dental, `.example` domains). Never real client names, contacts, host names, user names, home paths or screenshots.
- The target user is stock Hermes plus this plugin (spec D10). Do not add dependencies on Obsidian, extra profiles, agent fleets or external services.
- Use public Hermes plugin APIs only: no imports of Hermes private modules and no core patches.
- Core modules under `engagements/` must not import Hermes, so they stay unit-testable. This must print nothing:
  ```bash
  git grep -n -E "^(from|import) (hermes|agent|gateway|tools)\b" -- engagements/
  ```
- Runtime claims go in `docs/RUNTIME-EVIDENCE.md` with the surface named (CLI, TUI, Desktop, gateway). Source inspection is not a runtime result.
- A bug fix comes with a regression test that fails before the fix and passes after it.
- Commit messages explain why the change was made. No emojis in code, docs or commit messages.
- Releases, tags, catalog submissions and announcements are the maintainer's to make. Do not perform them from an agent session.

## Verify

Run the test and lint commands in the Development section of `README.md`, on Python 3.14 and 3.11. The examples in `README.md` are generated by `scripts/readme_examples.py` and checked by `tests/test_readme.py`; regenerate them instead of editing them by hand.
